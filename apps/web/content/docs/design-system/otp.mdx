The one-time-code flow is split into two **presentational** components in `src/shared/components/otp`. Neither knows about dialogs, routing or the auth API: each renders one step and reports what the user did through a callback. The caller decides where they live — today that is the full-screen `AuthOverlay`, but the same two components would work inside a drawer, a card on a page, or a checkout step.

| Component | Job | Reports |
| --- | --- | --- |
| `OtpStart` | Heading, description, a phone-or-email input with validation, submit | `onSubmit({ type, value })` |
| `OtpVerify` | Heading, six-digit code input, resend link, continue | `onVerify(code)`, `onResend()` |

Sequencing them is a separate concern handled by the `useOtpFlow` hook (see [the full flow](#full-flow)).

## OtpStart

Type a phone number or an email address. Validation runs on blur and on submit; the button stays disabled until the value is valid. The submitted payload is echoed under the form.

<ComponentPreview name="otp-start" />

```tsx
import { OtpStart } from "@shared/components/otp";

<OtpStart
  title="Become a Toyota iD member today"
  description="Unlock a smarter, more personalized experience."
  hint="Already a member? Sign in below"
  onSubmit={({ type, value }) => startOtp(type, value)}
/>
```

### Dark surface

The auth overlay renders the step over a photo, so it passes `surface="dark"`. That sets `data-surface="dark"` on the root and swaps the input to a white, borderless field.

## OtpVerify

Six-digit code input (`InputOTP` from `@ucmp/ui`, digits only, `autocomplete="one-time-code"`). Continue is enabled once all six digits are present; Resend clears the code and calls `onResend`.

<ComponentPreview name="otp-verify" />

```tsx
import { OtpVerify } from "@shared/components/otp";

<OtpVerify
  identifier="(***) ***-1234"
  onVerify={(code) => verifyOtp(code)}
  onResend={() => resendOtp()}
/>
```

## Full flow

`useOtpFlow()` (from `@features/auth`) owns the step and remembers the channel from step one so step two can show it masked. It has no opinion about the container — this demo renders it in a plain box; `AuthOverlay` renders the same thing full-screen.

<ComponentPreview name="otp-flow" defaultDevice="mobile" />

```tsx
import { useOtpFlow } from "@features/auth";
import { OtpStart, OtpVerify } from "@shared/components/otp";

function SignIn() {
  const flow = useOtpFlow();
  return flow.step === "start" ? (
    <OtpStart title="Sign in" description="…" onSubmit={flow.submitChannel} />
  ) : (
    <OtpVerify identifier={flow.identifier} onVerify={(code) => finish(code)} />
  );
}
```

<Callout title="Where the real flow lives">
`GuardedLink` → `useAuth().showOtpOverlay()` → `AuthProvider` → `AuthOverlay`, which renders exactly these two components inside a full-screen Base UI dialog. See [GuardedLink](/docs/design-system/guarded-link).
</Callout>
